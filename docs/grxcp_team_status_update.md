# GRXCP team update — PTA transport and GPU integration

**Date:** 2026-10-17  
**Status:** model regression improved; hardware/IP evidence gates remain open.

We added producer/consumer counter-wrap coverage to the PTA chiplet queue regression. The test initializes the empty eight-slot ring at `UINT32_MAX - 3`, publishes all eight descriptors so the producer tail wraps to `4`, observes the full ring while the first command is active, and checks that the consumer drains the descriptors once in index order across zero. The adjacent exact-capacity case also checks that a tail exactly one ring ahead is accepted and drains. The focused PTA chiplet queue test was built directly with `g++ -std=c++17 -O1 -g -Wall -Wextra -Werror` from the regression repository sources and passed **120 checks, 0 failed** across 128×64 and 256×64 twin configurations. This is twin/model evidence, not proof of the EIC implementation or board behavior.

## Blocker disposition

| Blocker | What is now documented or tested | What remains open |
|---|---|---|
| **MSI-X capability, allocation, and ISR** | Two vectors remain the provisional target: vector 0 CP completion and vector 1 aggregated PTA causes. The XRT AFU exports the CP interrupt pulse to its platform interrupt pin; the OPAE wrapper explicitly leaves that pulse unconsumed. A read-only PCI evidence collector is planned at tools/capture-pci-irq-evidence.sh (not yet in this tree). | No selected-function MSI-X Table Size/configuration export, actual OS vector-allocation record, or controlled ISR/counter-delta evidence is attached. The collector explicitly cannot prove allocation request/grant, handler registration, device causality, or ISR wakeup. OPAE CP completion routing remains unconnected. Keep Q1 **BLOCKED** pending capability, allocation, and handler evidence; resolve any <2-vector result explicitly. |
| **PTA queue depth, full behavior, and BUSY** | The transport design treats the host-memory ring as the queue and specifies serial consumption, full-ring overrun halt, and BUSY for work taken but not yet ended. The twin regression now covers exact full capacity and producer/consumer 32-bit wrap. | This does not establish the EIC's prefetch capacity, count whether active work consumes a chiplet-local slot, or prove hardware BUSY timing. The queue regression does not exercise `PTA_STATUS.BUSY` or calibration transitions. Owners must confirm the implemented queue/accounting contract and attach hardware or implementation-level boundary traces. Keep Q2–Q4 **BLOCKED** for implementation closure. |
| **CRC/retry fault evidence and measured link data** | CRC-on UCIe FLIT with adapter retry is the recorded board-plan/ICD posture; the design documents correctly distinguish this target from implementation proof. | No endpoint configuration/training export or CRC fault-injection/recovery/payload-integrity result is recorded. No measured per-direction payload rate, RTT distribution, retry counters, or actual credits/buffer budget is attached. The often-cited 57.6 GB/s and 100 ns are model assumptions, not measurements. Keep the physical-link gate **BLOCKED**. |
| **GPU BAR-to-EIC register transport** | The PTA register window is planned as MMIO in the GPU CXL.io BAR. | The BAR decode/bridge, named UCIe transaction, EIC endpoint/decode, address mapping, ordering/flush, completion, and error path have not been specified and tested end-to-end. Do not infer that sideband carries BAR traffic. Keep the route **OPEN/BLOCKED** pending an owner-approved diagram and read/write/readback evidence. |
| **Lossless GPU CP ring** | The GPU CP RTL has monotonic consumer-head telemetry and a low-read snapshot exposed through `Q_HEAD_SNAP_LO/HI`. The `cp_core` test source covers two commands across the physical ring boundary and checks completion plus the head snapshot. I configured a temporary build from the current checkout and built the test with Verilator 5.046; the run failed on its first AXI-Lite capability read (`axil_read: R never asserted`). This is a failing test result, not evidence that the ring path passed. | The runtime append path still copies at the producer tail and increments tail/sequence without checking free space against the consumer head; mid-command-line physical wrap is not supported there. The RTL test run stopped before reaching ring execution, and the test itself does not cover exact-full/backpressure, oversized-batch, delayed-acceptance, concurrent-producer, or end-to-end lossless behavior. The full monotonic-head capacity/backpressure contract is therefore **not yet implemented or proven**. |

## Requested next evidence

1. **GPU driver/platform owner:** capture PCI function identity and MSI-X Table Size; log requested and granted vectors and IRQ-to-vector mapping; run controlled CP/PTA interrupt tests with handler entry and counter deltas. Record XRT and OPAE separately.
2. **GPU dispatcher + EIC queue owners:** settle queue capacity and active-command accounting; specify backpressure/rejection and BUSY assertion/clear points; test exact capacity, over-capacity, calibration, recovery, and the single-read completion predicate against the implementation.
3. **GPU UCIe + EIC/link owners:** confirm endpoint CRC/retry/FLIT configuration, provide CRC error injection and recovery evidence, and measure payload throughput and RTT under unloaded and saturated traffic with transaction sizes, retry counters, credits, and buffers recorded.
4. **GPU BAR + EIC owners:** provide the actual register transaction route and exercise ID/safe-register read and write/readback, including ordering and error propagation.
5. **GPU runtime/RTL owners:** implement host-visible coherent consumer-head/capacity handling and producer backpressure (or a documented all-or-nothing alternative); add exact-full/resume, batch-over-capacity, wrap, delayed-acceptance, concurrency, and forward-progress tests. Keep the GPU CP ring distinct from any EIC/PTA-local queue.
